# Nextcloud with TLS — self-hosted Docker deployment

## Prerequisites

- A domain pointing at your server (e.g. `nextcloud.example.com`)
- Ports **80** and **443** forwarded to the server
- Docker, Docker Compose, and `make` installed
- `envsubst` (part of `gettext`) and `openssl` available on the host

## Deploy

```bash
cp .env.example .env
# Edit .env — fill in DOMAIN, EMAIL, DATA_PATH, USER_ID
make deploy
```

That's it. `make deploy` will:

1. Generate database passwords and store them in `.secrets` (only done once; re-running `make deploy` preserves existing secrets)
2. Create data directories at `DATA_PATH` (or `./nextcloud-data` if left empty)
3. Obtain a TLS certificate from Let's Encrypt via a temporary bootstrap nginx container
4. Generate `nginx.conf.generated` from the `nginx.conf` template
5. Start all containers (`docker compose up -d --build`)
6. Install a systemd timer that runs `cron.php` every 5 minutes for background jobs

After deployment, visit `https://DOMAIN` to complete the Nextcloud initial setup if needed.

### Background jobs

The systemd timer installed by `make deploy` runs Nextcloud's `cron.php` every 5 minutes.
After initial setup, go to **Administration Settings → Basic Settings → Background jobs**
and select **Cron** (instead of AJAX) to use it.

Some apps (e.g. Recognize) require this to be set to work correctly.

### Android app login

1. Log in via the browser, go to **Personal → Security → Devices & sessions**
2. Create a new app password — this generates a QR code to scan in the Android app

## Destroy

```bash
make destroy
```

Stops and removes all containers and uninstalls the systemd cron timer.
**Data at `DATA_PATH` is preserved.**

## Other commands

| Command | Description |
|---|---|
| `make logs` | Follow logs from all containers |
| `make cert-renew` | Force an immediate certificate renewal |
| `make reset-secrets` | Regenerate DB passwords (requires wiping the DB volume) |

## Certificate renewal

The `certbot` container automatically attempts renewal every 12 hours.
The HTTP server block in `nginx.conf` serves the ACME challenge at
`/.well-known/acme-challenge/` before redirecting to HTTPS, so renewal works
without any manual steps.

## File overview

| File | Purpose |
|---|---|
| `.env.example` | Template for operator config — copy to `.env` |
| `.env` | Operator config (git-ignored) |
| `.secrets` | Auto-generated DB passwords (git-ignored) |
| `nginx.conf` | nginx config template (`${DOMAIN}` placeholder) |
| `nginx.conf.generated` | Deployed nginx config (git-ignored, generated by make) |
| `nginx-bootstrap.conf` | Minimal nginx config used only during initial cert issuance |
| `Makefile` | Deployment automation |
| `systemd/` | Systemd service and timer units for Nextcloud background jobs |
| `Dockerfile` | Custom Nextcloud image (adds ffmpeg) |
